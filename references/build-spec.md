# 建站执行规范

## 一、先判断平台能力

| 环境 | 做法 | 预览方式 |
|---|---|---|
| 有网页 / 画布 / artifact 能力 | 用平台原生方式创建页面 | 平台内预览链接 |
| Claude Code / 本地 | 建静态站文件夹 | `open index.html` 或起本地服务 |
| 无网页能力 | 不声称已生成 | 交付完整代码 + 部署说明 |

本地静态站结构：

```text
site/
├── index.html
├── styles.css
├── script.js        # 只放复制、菜单等必要交互
└── assets/
    ├── portrait.jpg
    └── ...
```

预览：`open index.html`，或 `python3 -m http.server 8000` 后访问 `http://localhost:8000`。相对路径，便于整体迁移。

## 二、页面结构

- 单页优先：首屏 → 服务 → 真实案例 → 关于 → 联系。
- 导航用锚点即可，栏目多再拆多页。
- 语义化标签：`header` `nav` `main` `section` `footer`。
- 每个 `section` 有可读的标题；`h1` 全页唯一，层级不跳。
- 页面底部放联系方式与版权行；不放假备案号、假地址。

## 三、移动端与可访问性

- `<meta name="viewport" content="width=device-width, initial-scale=1">`。
- 移动端单列，断点 768px / 1024px 再展开。
- 正文不小于 16px，行高 1.6–1.8。
- 正文与背景对比度至少 4.5:1。
- 可点击元素高度至少 44px，间距足够，不靠悬停才能用。
- 图片有 `alt`，装饰图 `alt=""`。
- 键盘可聚焦，`:focus-visible` 可见。
- 动效尊重 `prefers-reduced-motion`。
- 浏览器缩到 320px 宽不横向滚动。

## 四、样式管理

- 颜色、字体、圆角、间距用 CSS 变量集中放在 `:root`。
- 配色最多 1 个主色 + 1 个点缀色 + 中性色阶，避免花。
- 能用系统字体就用，不随意引入未授权字体。
- 不使用第三方 CDN 图标库；需要图标时用内联 SVG 或文字。
- 一次只保留一个主 CTA（高对比实心按钮），其余为次按钮或文字链接。

## 五、按钮与链接（只做真的）

| 需求 | 正确做法 | 禁止 |
|---|---|---|
| 打电话 | `href="tel:13800138000"` | 写"立即拨打"却无链接 |
| 发邮件 | `href="mailto:name@example.com"` | 占位邮箱 |
| 加微信 | 显示微信号 + 一键复制按钮 | 直接跳转微信的假链接 |
| 微信二维码 | 用户提供的原图 | 自己生成二维码 / 占位图 |
| 预约 | 用户提供的真实预约链接 | 自己编的表单提交地址 |
| 表单 | 有真实后端 / 表单服务才做 | 前端假"提交成功" |
| 下载 | 文件确实存在且可访问 | 空 PDF、坏链接 |
| 外部链接 | `target="_blank" rel="noopener"` | 链到搜索页或首页 |

- 未提供真实目标的按钮：**隐藏**，或在页面内明确标"待补充"，并在交付说明中列出。不要做成看起来能点的假按钮。
- 每个按钮的动作与文案一致："预约试听"就真的去预约，不是跳到"关于我"。

## 六、内容与素材

- 只用用户提供或明确允许使用的文字、照片、Logo、证书、案例。
- 不用图库人物照片冒充本人；不用网上抓的图。
- 客户案例截图：打码 / 匿名需用户确认。
- 照片压缩到合理体积，设置宽高或 `aspect-ratio`，避免布局抖动。
- 不写用户没提供的数据、评价、头衔、年限。
- 不出现 Lorem ipsum 或"这里是介绍文字"这类开发者占位；宁可少一块。

## 七、SEO 与基础信息（有则加，无则略）

- `<title>`：姓名 / 品牌 + 服务 + 城市（如有）。
- `meta description`：一句真实、具体的介绍。
- `lang="zh-CN"`。
- favicon 可选；不做假 Logo。
- 社交分享图可选，用用户提供的照片。

## 八、修改与迭代

- 用户改文案：只改对应区块，不动结构。
- 用户改风格：先改 CSS 变量；不够再调版式。
- 用户加栏目：先确认有没有真实素材，再决定放置位置。
- 每次修改后重新自检按钮、移动端和标题层级。
