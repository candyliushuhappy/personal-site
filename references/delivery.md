# 交付与验收

## 交付说明（按实际填写，不套话）

```markdown
## 预览
- 本地文件：{path}（双击打开 / 起本地服务）
- 或预览链接：{url}
- 若当前环境无法生成网页：{说明原因 + 提供的可迁移代码与步骤}

## 已实现
- 单页 / 多页结构：{栏目列表}
- 联系方式按钮：{哪些、指向哪里}
- 移动端适配：{已验证到哪一步}

## 待补资料
- {缺失内容} → {补上后能加什么}

## 未验证 / 需要你确认
- {按钮、号码、链接、授权、第三方服务}
- 我只验证到 {实际验证范围}，其余请你在手机上再点一遍。

## 上线步骤
1. 确认信息与授权
2. 选择部署方式（由你操作或授权）
3. 绑定域名（如需）
4. 配置表单 / 预约服务（如需）
```

## 素材准备清单（发给用户的精简版）

- [ ] 姓名 / 品牌名，网站上显示的名称
- [ ] 一句话介绍：帮谁、解决什么
- [ ] 服务清单：人群、问题、交付物、价格是否公开
- [ ] 个人简介：短版（50 字）+ 长版（200–300 字）
- [ ] 头像 1 张 + 工作照 / 课堂照 2–3 张（已确认可公开）
- [ ] 资质证书照片（可选，需核对名称）
- [ ] 真实案例 1–3 个：背景、做法、结果（需授权，可匿名）
- [ ] 学员 / 客户评价 1–3 条（需授权）
- [ ] 联系方式：微信 ID / 手机 / 邮箱（确认公开）
- [ ] 微信二维码原图（如需）
- [ ] 预约链接 / 客服流程（如有）
- [ ] Logo、品牌色、字体偏好（如有）

## 上线验收清单

**信息**
- [ ] 姓名、头衔、机构名称逐字核对
- [ ] 证书、年限、资质与原件一致
- [ ] 价格、服务范围、适合人群表述准确
- [ ] 没有无法证明的数字或"第一 / 最好"类表述

**授权**
- [ ] 本人照片与肖像权
- [ ] 儿童照片、姓名、作品有监护人授权
- [ ] 客户案例与评价有当事人授权
- [ ] 第三方 Logo、图片、字体已获授权或替换

**功能**
- [ ] 每个按钮点一遍，动作与文案一致
- [ ] 电话可拨、邮箱可发、微信可复制
- [ ] 预约 / 下载 / 外链真实可用
- [ ] 二维码扫码结果正确
- [ ] 没有假表单、假"提交成功"

**设备**
- [ ] 手机竖屏：文字可读、按钮可点、无横向滚动
- [ ] 平板 / 电脑：版式不散、图片不糊
- [ ] 微信内置浏览器打开正常（如需朋友圈传播）
- [ ] 图片全部加载，无破图

**合规与部署**
- [ ] 如收集个人信息，有必要的隐私说明
- [ ] 域名、HTTPS、部署由用户操作或明确授权
- [ ] 表单、预约、支付等外部服务已真实接通
- [ ] 不擅自发布到外部平台

## 部署说明（按需解释，不代操作）

- **独立域名**：需用户自行注册、实名、解析 DNS，通常还需备案（视服务商与地区）。
- **托管**：Netlify / Vercel / GitHub Pages 等可拖拽或连接仓库部署；账号与授权归用户。
- **表单 / 预约**：需要表单服务（如 Formspree、飞书表单）或自有后端；没接通前只展示联系方式。
- **第三方统计 / 客服**：需用户提供代码与授权，不默认接入。

## 测试边界

- 说明实际测过什么：本地打开、手机宽度模拟、按钮链接检查。
- 未实际部署、未在真机测试、未扫码验证的部分，明确标"待用户验证"。
- 不写"已上线""已测试通过"，除非真的做过。
